## ٣) خطوة إلزامية: نشر قواعد الأمان

قواعد المشروع الحالية تمنع أي مجموعة غير المعروفة مسبقاً، فلن يعمل
`family_config` ولن يستطيع هذا الحساب قراءة `students` أو `records`
قبل نشر القواعد الجديدة.

```bash
# ١) انسخ ملف القواعد إلى مجلد سجل متابعة الحلقات
copy "Brave Family Website\firestore.rules" "daragati\firestore.rules"

# ٢) انشره
cd daragati
firebase deploy --only firestore:rules
```

**ما الذي تغيّر عن قواعدك الحالية؟** ثلاثة أشياء فقط:

1. دالة جديدة `isFamilyOwner()` تتحقق من البريد المصرّح له.
2. أُضيف `isFamilyOwner()` إلى **صلاحية القراءة فقط** في
   `students` و `records` و `pointsAdjustments`. لا كتابة ولا حذف.
3. قسم جديد `match /family_config/{docId}` يقرؤه ويكتبه هذا الحساب وحده.

كل ما عدا ذلك في القواعد باقٍ حرفياً كما هو، فلا يتأثر سجل متابعة
الحلقات بشيء.

## ٤) التشغيل

الموقع صفحات ثابتة، لكن `type="module"` يحتاج خادماً (لا يعمل من
`file://`). أي طريقة تكفي:

```bash
# Python
python -m http.server 5500

# أو Node
npx serve .

# أو Firebase Hosting كموقع منفصل
firebase hosting:sites:create brave-family
firebase deploy --only hosting
```

ثم افتح `http://localhost:5500/index.html`.

## ٥) الاستخدام

1. **سجّل الدخول** بالبريد المصرّح له.
2. افتح **⚙️ الإعداد**: اختر المرحلة (ابتدائي / متوسط / ثانوي)،
   تظهر أسماء طلابها من Firestore، علّم على أفراد العائلة.
   يمكنك التنقل بين المراحل الثلاث والتحديد يبقى محفوظاً في الذاكرة،
   ثم اضغط **💾 حفظ العائلة** فتُكتب القائمة كاملة في
   `family_config/brave_family`.
3. ارجع إلى **📊 اللوحة**.

## ٦) ماذا تعرض اللوحة

| القسم | التفصيل |
|---|---|
| 🏅 مجاميع النقاط | مجموع نقاط العائلة كلها: الأسبوع، الشهر، منذ البداية |
| 🚨 مراقب الغياب | تنبيه أحمر بأسماء من حضورهم «غائب» اليوم، مع تمييز «متأخر» و«معذور» |
| 📆 نشاط اليوم | جدول لكل فرد: الحضور، نقاط اليوم، الصفحات، المصحف والزي |
| 👥 نقاط الأفراد | بطاقة لكل فرد مع مركزه وأيامه وغيابه — تتبدّل مع أزرار الفترة |
| 📊 الترتيب التفصيلي | جدول تنازلي بشريط نسبة لكل فرد |
| 🤝 بحاجة إلى دعم | ترتيب **تصاعدي** — الأقل نقاطاً في الأعلى، بصياغة تشجيعية لا عتاب فيها |

أزرار **الأسبوع / الشهر / منذ البداية** تُعيد حساب الأقسام الثلاثة
الأخيرة فوراً بلا أي طلب جديد من الخادم.

## ٧) ملاحظات تقنية

* **حساب النقاط** يطابق السجل الأصلي تماماً:
  `نقاط الفترة = مجموع records.points + مجموع pointsAdjustments.delta`
* **الأسبوع** يبدأ الأحد وينتهي السبت (نفس تعريف `weekRange` الأصلي).
* **كل التواريخ محلية** (لا `toISOString`)، فلا يُحسب ما بعد منتصف
  الليل على اليوم السابق.
* **مطابقة الهوية**: أرقام الطلاب تتغيّر عند حذف طالب وإعادة الترقيم،
  لذلك تُحفظ `uid` الثابتة مع كل عضو، وتُعاد مطابقة الأرقام من مجموعة
  `students` عند كل تحميل — فلا تُنسب نقاط طالب إلى آخر أبداً.
* **لا فهارس مركّبة مطلوبة**: كل استعلام مبني على شرط واحد
  (`where('level','==',...)`) والتصفية الزمنية تتم محلياً.
* **الرسم فوري**: لا شاشة تحميل ولا إخفاء للصفحة؛ الهيكل يظهر مباشرة
  وتُملأ الأقسام عند وصول البيانات.
* **قراءة فقط**: هذا الموقع لا يكتب في `records` ولا `students` ولا
  `pointsAdjustments` إطلاقاً. المستند الوحيد الذي يكتبه هو
  `family_config/brave_family`.

## ٨) استكشاف الأخطاء

| ما تراه | السبب والحل |
|---|---|
| «الوصول مرفوض من قواعد الأمان» | لم تُنشر `firestore.rules` بعد — راجع الخطوة ٣ |

| «لا يوجد طلاب في هذه المرحلة» | `levels/{id}.studentCount` = صفر في قاعدة البيانات |
